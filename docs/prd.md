# CURI MVP 제품 요구사항

## 1. 제품 목표
CURI는 `웹컨텐츠개발` 수강생이 1~15주 학습 흐름, 이번 주 준비 행동, 공식 문서 기반 답변을 한 화면에서 확인하고, 동의 기반 학습 팁을 공식 정보와 분리해 공유하는 웹 앱이다.

## 2. 성공 시나리오
심사위원 한 명이 로그인 없이 한 브라우저 세션에서 다음 흐름을 완료한다.

1. 1~15주 로드맵에서 현재 주차와 중간고사·기말 프로젝트를 확인한다.
2. 현재 주차의 주제·학습목표·준비·과제·체크리스트를 확인하고 항목 하나를 완료한다.
3. 공식 강의정보에 질문하고 근거 문구와 출처 배지가 붙은 답변을 받는다.
4. 공식 문서에 없는 질문에서 추측 없는 `근거 없음` 답변을 확인한다.
5. 수강생 학습 팁 집계를 확인하고 구조화 설문을 제출해 집계가 갱신되는 것을 본다.
6. 읽어주기와 키보드만으로 핵심 흐름을 이용한다.

## 3. 사용자
- 주 사용자: 웹컨텐츠개발 과목 수강생
- 데모 사용자: 심사위원
- MVP에 없는 사용자: 교수자·조교 관리자

## 4. 정보 계층

### 4.1 실제 강의계획서
원본은 `광주대 컴퓨터공학과 강의계획서.zip` 안의 `컴공/웹컨텐츠개발.pdf`다. 앱은 원본 PDF를 직접 노출하거나 색인하지 않는다. 다음 정보만 개인정보 제거 파생 데이터로 사용한다.

- 과목명, 개요, 교과목 목표
- 평가 비율과 평가 방식
- 1~15주 수업 주제, 학습목표, 수업방법, 과제

교수자 이름, 전화번호, 이메일, 면담 시간·장소, 민원 연락처는 저장·표시·색인하지 않는다. 파생 데이터에는 `sourceKind: actual`과 원본 파일명을 기록하고 화면에 `실제 강의계획서` 배지를 표시한다.

### 4.2 데모 보충 강의정보
실제 문서에 없는 구체적인 설치 준비, 공지, 체크리스트, 근거 없음 시나리오는 팀이 만든 가상 문서로 보충한다. 모든 레코드에 `sourceKind: demo`를 기록하고 화면에 `데모 데이터` 배지를 표시한다. 실제 강의계획서 내용처럼 위장하지 않는다.

### 4.3 수강생 경험정보
다음 구조화 응답만 수집한다.

- 선수지식 필요도: 낮음(1), 보통(2), 높음(3)
- 실습 비중: 낮음(1), 보통(2), 높음(3)
- 과제량: 적음(1), 보통(2), 많음(3)
- 준비 태그: `HTML/CSS 기초`, `VS Code 설치`, `Chrome 설치`, `GitHub 계정`, `JavaScript 기초`
- 수집 동의: 필수

자유서술, 이름, 학번, 이메일, IP 주소는 수집하지 않는다. 과목별 유효 응답이 5건 미만이면 평균과 태그 빈도를 숨긴다. 초기 12건은 `isDemo: true`로 저장하고 `데모 데이터`라고 표시한다.

## 5. 기능 요구사항

### FR-1 학기 로드맵
- 웹컨텐츠개발 1~15주를 주차 순서로 표시한다.
- 현재 주차는 데모 기준 7주차로 고정한다.
- 1~6주차는 완료, 7주차는 현재, 8~15주차는 예정 상태다.
- 8주차 중간고사와 15주차 기말 프로젝트를 이정표로 표시한다.
- 각 주차는 주제, 학습목표, 과제, 출처 배지를 제공한다.

### FR-2 이번 주 학습 코치
- 7주차 자바스크립트 기초를 표시한다.
- 실제 문서의 학습목표와 `기말 프로젝트 제안서 제출`을 표시한다.
- 데모 보충 정보인 `VS Code 설치`, `Chrome 개발자도구 확인`, `JavaScript 실행 환경 확인`을 별도 출처 배지와 함께 표시한다.
- 체크리스트 완료 상태는 브라우저 localStorage에 저장한다.

### FR-3 출처형 Q&A
- 질문을 1~200자로 제한한다.
- 서버는 공식 강의정보 청크에서 질문 단어가 포함된 근거를 최대 4개 선택한다.
- 근거가 없으면 Bedrock을 호출하지 않고 `공식 문서에서 근거를 찾지 못했습니다. 담당자에게 확인해 주세요.`를 반환한다.
- 근거가 있으면 Amazon Bedrock `global.anthropic.claude-sonnet-5`를 호출한다.
- 프롬프트는 제공된 근거 밖 추측을 금지한다.
- 응답은 답변, 근거 문구, 문서명, 주차, `actual|demo` 출처 유형을 포함한다.
- Bedrock 호출 실패 시 근거 목록은 유지하고 `AI 답변을 생성하지 못했습니다. 아래 공식 근거를 확인해 주세요.`를 반환한다.
- 수강생 경험정보는 검색·프롬프트·답변 근거에 포함하지 않는다.

### FR-4 수강생 학습 팁 집계
- 초기 데모 응답 12건의 응답 수, 세 척도 평균, 준비 태그 빈도를 표시한다.
- 집계 영역에 `수강생 참고 정보`와 `데모 데이터 포함`을 표시한다.
- 5건 미만이면 수치 대신 `응답 5건부터 집계를 공개합니다.`를 표시한다.

### FR-5 수강생 학습 팁 제출
- 세 척도, 준비 태그 1개 이상, 동의를 필수 검증한다.
- 브라우저가 생성한 임의 세션 토큰의 SHA-256 해시만 저장한다.
- 데이터베이스의 `(course_id, session_hash)` 고유 제약으로 중복을 차단한다.
- 성공 시 최신 집계를 반환하고 UI를 즉시 갱신한다.
- 중복 제출은 HTTP 409와 `이 브라우저에서는 이미 학습 팁을 제출했습니다.`를 반환한다.

### FR-6 접근성
- 모든 조작 요소를 키보드로 사용할 수 있다.
- 포커스 표시를 숨기지 않는다.
- 주요 영역은 제목·랜드마크·라벨로 연결한다.
- 체크리스트, 질문, 제출 결과는 `aria-live`로 상태 변화를 알린다.
- 읽어주기는 Web Speech API `speechSynthesis`를 사용하며 시작·중지 버튼을 제공한다.
- Web Speech API가 없으면 버튼을 비활성화하고 대체 설명을 표시한다.

## 6. 비기능 요구사항
- Node.js 20 이상, pnpm 사용
- Next.js App Router + TypeScript 단일 앱
- SQLite 파일은 Git에 포함하지 않는다.
- 로컬에서 AWS 자격 증명을 만들지 않는다.
- S3·Bedrock 실호출은 EC2 인스턴스 역할에서만 수행한다.
- AWS 리전은 환경에서 상속하고 코드에 다른 리전을 하드코딩하지 않는다.
- S3 버킷 이름은 `hackathon-e2-t01-` 접두사를 사용한다.
- deploy, destroy, EC2 종료·재시작은 사용자 명시 전 실행하지 않는다.

## 7. 제외 범위
에브리타임 크롤링·로그인 자동화, 외부 강의평 원문, 자유서술 후기, 교수자 평판 판단, 실제 성적 평가, 모바일 앱, 결제, 관리자 화면, 운영자 인사이트, 문서 변경 비교, 고급 개인화, 사용자 계정, 신고·검토 기능은 구현하지 않는다.

## 8. 완료 기준
- `docs/demo-script.md`의 6단계를 로컬 브라우저에서 완료한다.
- 로드맵·이번 주 코치의 실제/데모 출처 배지가 데이터와 일치한다.
- Q&A 근거 없음과 Bedrock 실패가 명시적으로 구분된다.
- 수강생 팁 제출 전후 응답 수와 집계가 바뀐다.
- 같은 세션 중복 제출이 서버에서 차단된다.
- 키보드 탐색과 읽어주기가 실제 동작한다.
