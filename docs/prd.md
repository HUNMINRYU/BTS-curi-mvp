# CURI MVP 제품 요구사항

## 1. 제품 목표
CURI는 학생의 전공·관심·목표·학습 방식을 이해해 과목과 추천 이유를 제시하고, 시간표에서 과목별 준비 행동·출처형 Q&A까지 이어 주는 AI 수업 내비게이터다.

## 2. 성공 시나리오
심사위원은 학생·교수 데모 계정으로 다음 흐름을 완료한다.

1. 학생 로그인 후 7단계 온보딩을 완료한다.
2. 프로필에 맞는 과목 3~5개와 추천 이유를 확인한다.
3. 추천 과목을 시간표에 담고 상세로 이동한다.
4. 대표 과목의 15주 로드맵·이번 주 준비·개인 목표 체크리스트를 확인한다.
5. 공식 강의정보 기반 답변과 근거 없음 정직 응답을 확인한다.
6. 체크리스트 보상과 구조화 수강생 팁 집계를 확인한다.
7. 교수 계정에서 근거 없음 질문과 팁 집계를 확인한다.
8. 읽어주기와 키보드만으로 핵심 흐름을 이용한다.

## 3. 사용자
- 학생: 온보딩, 추천, 시간표, 과목 상세, Q&A, 체크리스트, 학습 팁을 사용한다.
- 교수: 읽기 전용 리포트에서 근거 없음 질문과 팁 집계를 확인한다.
- 심사위원: 사전 생성된 학생·교수 데모 계정을 전환해 전체 동선을 확인한다.

회원가입·비밀번호·이메일 인증·계정 관리는 제공하지 않는다.

## 4. 정보 계층

### 4.1 실제 강의정보
원본 강의계획서에서 과목명, 학과, 개요, 목표, 난이도, 선수지식, 1~15주 주제·목표·과제만 개인정보 제거 파생 데이터로 사용한다. 교수 이름·전화번호·이메일·면담·민원 정보는 저장·표시·색인하지 않는다. 실제 파생 데이터는 `sourceKind: actual`과 `실제 강의계획서` 배지를 갖는다.

### 4.2 데모 데이터
시간표 요일·시간, 보충 준비물, 초기 팁 12건처럼 팀이 만든 정보는 `sourceKind: demo` 또는 `isDemo: true`와 `데모 데이터` 배지를 갖는다.

### 4.3 수강생 경험정보
선수지식 필요도·실습 비중·과제량을 1~3 척도로, 준비 태그를 허용 목록에서 수집한다. 동의는 필수다. 자유서술·이름·학번·이메일·IP를 받지 않는다. 5건 미만이면 평균과 태그 빈도를 숨긴다.

## 5. 기능 요구사항

### FR-1 학기 로드맵
- 대표 과목 `웹컨텐츠개발`의 1~15주를 순서대로 표시한다.
- 현재 7주차, 완료 1~6주차, 예정 8~15주차를 구분한다.
- 8주차 중간고사와 15주차 기말 프로젝트를 이정표로 표시한다.
- 주차별 주제·목표·과제·출처 배지를 제공한다.

### FR-2 이번 주 학습 코치
- 7주차 주제·실제 목표·과제와 데모 준비물을 표시한다.
- 학생의 온보딩 목표를 체크리스트 안내에 반영한다.
- 완료 상태를 로그인 사용자별 `checklist_state`에 저장한다.

### FR-3 출처형 Q&A
- 질문은 1~200자다.
- `/api/qa`는 loopback retriever에 질문과 `courseId`를 보내고, retriever는 EC2 로컬 FAISS 인덱스의 같은 `courseId` 청크만 최대 5개 반환한다.
- sidecar는 질문 임베딩에 Bedrock Titan을 사용하고 로컬 `index.faiss`·`chunks.jsonl`만 읽는다. 런타임은 S3나 `CURI_DOCUMENT_BUCKET`을 읽지 않는다.
- 근거가 없으면 Bedrock을 호출하지 않고 `not_found`를 반환하며 질문을 `qa_logs`에 기록한다.
- 근거가 있으면 Bedrock `global.anthropic.claude-sonnet-5`에 근거만 전달한다.
- 모델 실패는 `model_error`와 근거 목록을 유지한다.
- 수강생 팁은 답변 근거에 포함하지 않는다.
- **계획됨(배포 미연결):** S3 `documents/` PDF에서 로컬 인덱스를 재생성하려면 `scripts/rag_indexer.py`를 수동으로 실행한다.

### FR-4 수강생 학습 팁 집계
- 초기 데모 응답 12건의 응답 수, 세 평균, 태그 빈도를 표시한다.
- `수강생 참고 정보`와 `데모 데이터 포함`을 명시한다.
- 5건 미만이면 `응답 5건부터 집계를 공개합니다.`를 표시한다.

### FR-5 수강생 학습 팁 제출
- 로그인한 학생만 제출한다.
- 세 척도, 준비 태그 1개 이상, 동의를 검증한다.
- `UNIQUE(course_id, user_id)`로 사용자당 과목 1회를 보장한다.
- 성공 시 최신 집계를 반환해 즉시 갱신한다.
- 중복은 HTTP 409와 `이 계정은 이미 학습 팁을 제출했습니다.`를 반환한다.

### FR-6 접근성
- 모든 조작 요소를 키보드로 사용할 수 있고 포커스 표시를 유지한다.
- 랜드마크·제목·라벨·`aria-live`를 사용한다.
- Web Speech API로 핵심 안내 읽기 시작·중지를 제공한다.
- Web Speech API가 없으면 버튼을 비활성화하고 설명을 표시한다.

### FR-7 온보딩
- 로그인한 학생이 전공→관심분야→목표→진로→학습스타일→투자 시간→비선호 분야 순서로 진행한다.
- 각 단계는 단일 선택 칩과 건너뛰기를 제공한다.
- 완료 시 `user_profile` 한 행으로 저장하고 추천 화면으로 이동한다.
- 완료된 프로필이 있으면 다시 온보딩하지 않는다.

### FR-8 과목 추천
- 카탈로그에서 비선호 태그를 먼저 제외한다.
- 전공·관심분야·목표 키워드·시간 조건을 결정론적으로 점수화해 후보 10~15개를 만든다.
- Bedrock은 후보 중 3~5개와 전공 연계·목표 부합·시간 적합 중 하나 이상의 근거가 있는 이유를 반환한다.
- 모델 실패 시 결정론적 상위 결과를 유지하고 `AI 추천 이유를 생성하지 못했습니다.`를 표시한다.
- 학생 프로필 밖 내용을 추천 이유로 만들지 않는다.

### FR-9 시간표
- 추천 과목을 시간표에 담고 뺄 수 있다.
- 선택은 `user_courses`에 저장되어 새로고침 후 유지된다.
- 월~금 데모 프리셋 요일·시간의 주간 그리드로 표시한다.
- 과목 셀은 링크이며 키보드로 상세에 진입한다.

### FR-10 로그인과 역할
- `/login`에서 학생·교수 사전 생성 계정을 선택한다.
- 서버는 추측 불가능한 세션 ID의 HttpOnly·SameSite=Lax 쿠키를 발급하고 SQLite 세션에 연결한다.
- 학생은 학생 화면, 교수는 `/professor`로 이동한다.
- 학생의 교수 화면 접근과 교수의 학생 변경 API 접근은 403 또는 역할별 리다이렉트로 차단한다.
- 로그아웃은 서버 세션과 쿠키를 제거한다.

### FR-11 교수 리포트
- 교수만 `/professor`를 볼 수 있다.
- 과목별 근거 없음 질문의 질문 문구·발생 시각·횟수와 구조화 팁 집계를 읽기 전용으로 표시한다.
- 학생 이름·프로필·자유서술은 표시하지 않는다.
- 업로드·답글·공지 작성 기능은 만들지 않는다.

## 6. 비기능 요구사항
- Node.js 20.9 이상, pnpm, Next.js App Router + TypeScript 단일 앱.
- SQLite 파일은 Git에 포함하지 않는다.
- 현재 배포의 Q&A는 EC2 로컬 FAISS 사이드카와 Bedrock을 사용한다. S3 문서 동기화·재색인은 계획된 수동 절차로 아직 런타임에 연결하지 않았다.
- 계획된 S3 재색인에서 boto3의 리전·자격 증명은 기본 공급자 체인에서 해석한다. Access Key는 만들거나 저장하지 않는다.
- deploy/destroy와 EC2 종료·재시작은 사용자 명시 승인 전 금지한다.
- 기존 네이비·퍼플 디자인, 학교안심 알림장 폰트, CURI 캐릭터 자산을 유지한다.

## 7. 제외 범위
외부 강의평 원문, 자유서술 후기, 교수 평판, 개인 일정 캘린더, 알림, 회원가입, 비밀번호 재설정, 이메일 인증, 모바일 앱, 결제, 실제 성적 평가, 대댓글·신고·차단·금칙어, 업로드 관리자 기능, 관리형 벡터 DB, 학기 전후 능력 그래프와 말투 모드(핵심 완료 전).

## 8. 완료 기준
- 핵심 학생·교수 10단계 데모 동선을 로컬 브라우저에서 완료한다.
- 서로 다른 두 프로필의 추천 결과 또는 순위가 달라지고 비선호 과목은 0건이다.
- 시간표가 새로고침 후 유지되고 대표 과목 상세로 연결된다.
- Q&A 세 상태와 근거 없음 로그가 검증된다.
- 팁은 `(course_id, user_id)`로 중복 차단된다.
- 학생은 교수 리포트를 볼 수 없고 교수는 리포트를 읽을 수 있다.
- 키보드 탐색과 읽어주기가 실제 동작한다.
