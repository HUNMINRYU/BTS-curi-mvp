## 요약

13장 중 **4장이 발표용이 아닙니다.** 아키텍처 슬라이드가 빈 채로 두 번 들어가 있고, 제작용 메모가 그대로 노출됩니다. 화면 구상은 실제 서비스가 아니라 스톡 일러스트입니다. 또한 표지·마무리의 "AI 커리큘럼 안내 챗봇"은 팀이 이미 버린 포지셔닝이라, 슬라이드 3의 "커리큘럼을 분석하는 AI가 아니라 학생을 이해하는 AI"와 정면으로 충돌합니다.

가장 시급한 것은 **8·9번(빈 아키텍처 슬라이드)** 입니다. AWS 활용도가 심사 배점의 핵심인데 그 자리가 비어 있습니다.

## 구조 문제

1. **슬라이드 순서가 목차 순서와 다릅니다.** 목차는 01 팀 소개 → 07 향후 계획인데, 실제 배열은 배경(02) → … → 향후 계획(07) → **팀 소개(01)** 순입니다. 팀 소개를 앞으로 옮기거나 목차에서 07 뒤로 내리세요.
2. **페이지 번호가 헤더 섹션 번호와 어긋납니다.** (헤더 02 / 번호 01, 팀 소개 헤더 01 / 번호 08) 하단 번호를 통일하거나 없애세요.
3. **스크립트에 있는데 슬라이드가 없는 섹션이 3개입니다.** AI·AWS 활용, KIRO 활용, 데이터 신뢰성. 발표자가 말할 때 화면이 따라가지 않습니다. 최소한 AWS 아키텍처 1장과 데이터 신뢰성 1장은 필요합니다.
4. **최종 슬라이드 수 제안: 13 → 13** (중복 1장 삭제, 메모 1장 삭제 후 아키텍처 1장·데이터 신뢰성 1장 추가)

## 8번(아키텍처) 슬라이드에 넣을 재료

현재 배포 구성과 계획된 S3 재색인 절차를 분리해 도식화하면 됩니다.

```
[브라우저]
   ↓
[Amazon EC2 · ap-northeast-2]
   nginx :80 → Next.js :3000 (systemd)
   ├─ SQLite 단일 파일 (사용자·시간표·체크리스트·팁·질문로그·포인트)
   └─ FAISS 검색 사이드카 :8788 (systemd) → /var/lib/curi/rag/index.faiss
                                                   (현재 배포의 사전 생성 인덱스)
                                                      ↓
[Amazon Bedrock] Claude Sonnet(추천 이유·답변 생성) + Titan Text Embeddings v2(질의 임베딩)

[계획됨 · 현재 배포 미연결]
[Amazon S3] documents/ 강의계획서 PDF ── 수동 RAG 인덱서 ──┘
                                          (PDF 청크 임베딩 후 로컬 인덱스 재생성)
```

말로 붙일 한 줄: "질문이 오면 EC2 안의 검색이 먼저 로컬 근거를 찾고, 근거가 있을 때만 Bedrock을 부릅니다. S3 재색인은 아직 배포에 연결하지 않은 계획입니다."

리포지토리 `docs/architecture.md`에 같은 내용의 mermaid 다이어그램이 있으니 렌더해서 이미지로 붙여도 됩니다.
