# CURI MVP 결정 기록

## D-1 데모 과목
**결정:** 실제 강의계획서가 있는 `웹컨텐츠개발` 한 과목만 지원한다.

**근거:** 원본 `웹컨텐츠개발.pdf`에 개요, 목표, 평가, 1~15주 계획이 있어 출처형 데모를 만들 수 있다. 다과목 지원은 데이터 모델과 탐색 UI를 늘리지만 심사 동선에 필요 없다.

## D-2 문서 출처
**결정:** 개인정보 제거 실제 파생 데이터와 표시된 가상 보충 데이터를 함께 사용한다.

**규칙:** 모든 강의정보 레코드는 `sourceKind: actual | demo`를 갖는다. UI와 Q&A 출처에서 각각 `실제 강의계획서`, `데모 데이터`를 표시한다. 원본 PDF의 교수 이름·연락처·이메일·면담정보·민원 연락처는 저장·노출·색인하지 않는다.

## D-3 애플리케이션 구조
**결정:** Next.js App Router 모노리스 하나를 사용한다.

**근거:** 별도 FastAPI, CORS, 두 프로세스 배포를 제거한다. 기존 Python 파일은 AWS 연결 검증 예제로만 남고 제품 런타임에는 포함하지 않는다.

## D-4 데이터베이스
**결정:** 로컬과 EC2 모두 SQLite를 사용한다.

**근거:** 단일 EC2·단일 데모 사용자 범위에서 외부 DB 운영이 불필요하다. 사용자 팁, 중복 제출 제약, 체크 가능한 집계를 한 파일에서 처리한다.

## D-5 인증
**결정:** 사용자 로그인은 구현하지 않는다. AWS는 EC2 인스턴스 역할만 사용한다.

**근거:** 로그인은 심사 동선에 없고, AWS Access Key는 전역 가드에서 금지한다. 브라우저 세션 토큰 해시와 DB 고유 제약으로 데모 중복만 차단한다.

## D-6 Q&A 검색
**결정:** 한 과목의 정제 청크에 대한 결정론적 키워드 검색을 사용하고 FAISS·외부 벡터 DB를 사용하지 않는다.

**근거:** 문서 규모가 작아 벡터 인덱스가 품질보다 설치·인덱스 장애를 늘린다. 검색 결과와 근거 없음 동작을 로컬에서 완전히 검증할 수 있다.

## D-7 생성 모델
**결정:** `global.anthropic.claude-sonnet-5`를 Amazon Bedrock에서 호출한다.

**근거:** 조별 EC2 역할로 기존 연결 테스트가 확인된 inference profile이다. 리전은 SDK 기본 공급자 체인에서 상속한다. 근거가 없으면 모델을 호출하지 않는다.

## D-8 S3 사용
**결정:** 배포 단계에서 정제 강의정보 JSON을 `hackathon-e2-t01-docs`에 저장하고 앱 시작 시 동기화한다. 로컬은 동일 형식의 저장소 파일을 사용한다.

**근거:** 공식 문서 저장이라는 데모 요구를 충족하면서 로컬 데모를 AWS에 종속시키지 않는다. S3 실패 시 마지막 로컬 정제 데이터를 사용하고 상태를 로그로 남긴다.

## D-9 수강생 학습 팁
**결정:** 3단계 척도 3개와 선택형 준비 태그만 수집하고, 과목별 5건부터 집계를 공개한다.

**근거:** 자유서술·원문 공개·콘텐츠 검토를 제거하고 교수 평가가 아닌 수업 준비 지원에 한정한다.

## D-10 중복 제출
**결정:** 브라우저 세션당 과목 1회를 서버 DB의 고유 제약으로 차단한다.

**한계:** 쿠키 삭제나 다른 브라우저는 새 세션으로 간주한다. 실제 운영 인증·부정 제출 방지는 MVP 범위 밖이다.

## D-11 접근성
**결정:** 시맨틱 HTML, 키보드 탐색, 포커스 표시, `aria-live`, Web Speech API 읽어주기를 핵심 기능과 함께 구현한다.

**근거:** 별도 접근성 화면보다 실제 심사 흐름에서 검증 가능하고 범위가 작다.

## D-12 배포 경계
**결정:** 로컬 데모가 완료되기 전 AWS 배포를 하지 않는다. deploy/destroy, EC2 종료·재시작은 사용자 명시 전 금지한다.
