작성: 2026-09-01 17시. 팀 카카오톡 합의(`KakaoTalk_Chat_2026-09-01-17-08-14.txt`)를 반영한 개정판.
**역사적 계획 문서:** 이 파일의 S3 업로드·FAISS 금지 서술은 당시 계획이며 현재 배포 사실이 아니다. 현재 배포의 Q&A는 로컬 FAISS 인덱스를 읽고, S3 문서 재색인은 아직 연결되지 않은 계획이다. 현재 동작은 `docs/architecture.md`를 따른다.

## 확정된 제품 방향 (피벗)

슬로건: **"CURI는 커리큘럼을 분석하는 AI가 아니라, 학생을 이해하는 AI입니다."**

- 기존: 단일 과목(웹컨텐츠개발) 수업 내비게이터
- 확정: **온보딩 커스터마이징 → 과목 추천(+추천 이유) → 시간표 메인 → 과목 상세 내비게이터**로 확장. 기존 MVP(로드맵·코치·Q&A)는 폐기가 아니라 "과목 상세 페이지"로 편입된다.
- 사용자: 학생(메인) + 교수(읽기 전용 리포트). 로그인 필수(D-5 개정), 데모 계정 방식.

## 채택 / 축소 / 제외 판정 (카카오톡 항목별)

| 항목 | 판정 |

| 과목 추천 + **추천 이유 필수** | ✅ 채택. 결정론적 사전 필터(비선호 제외·키워드 매칭) → Bedrock이 상위 3~5개 + 프로필 근거 이유 생성 |
| 과목별 선수지식·사전 자료 추천 | ✅ 채택. 카탈로그 필드(선수지식)로 포함 |
| 시간표 입력 → 메인 화면, 과목 클릭 → 상세 | ✅ 채택. 추천 과목을 "시간표에 담기"로 추가. 시간·요일은 데모 프리셋 |
| 상세 페이지: 주차 로드맵 + 준비물 + 개인 목표 맞춤 체크리스트 | ✅ 채택. 기존 FR-1·FR-2 재사용. 대표 과목(웹컨텐츠개발)만 풀 디테일 |
| 체크리스트 성취도 → 보상 | ✅ 축소 채택. 마스코트 1종이 완료율로 3단계 성장(기존 결정 유지) |
| 학기 전/후 개인 능력 변화(집중도·성취도 등) | ⚠️ 여유 시. 실데이터가 없으므로 `데모 데이터` 배지를 단 시뮬레이션 그래프로만 |
| 개인 일정 캘린더 | ❌ 제외 권고(원문도 물음표). 일정 CRUD는 범위 폭발, 시간표가 데모 가치를 대체 |
| 기존 LMS는 번거롭다 | 발표 문제 정의 슬라이드로 (feature-triage의 "주 1회 의무 vs 매일 자발" 프레임) |

기존 범위 중 유지: 출처형 Q&A(대표 과목), 수강생 팁 집계(재사용), 교수 리포트, 접근성. 계속 제외: 알림(SNS/SES 없음), 강의평 원문, 대댓글·신고·금칙어, 회원가입, 모바일 앱.

## 모든 브리핑 공통 제약

- "구현+검증 출력까지만 하고 종료. 커밋 금지. 다중 관점 자체 리뷰 금지 — 검토는 별도 critic이 수행한다."
- **AWS는 EC2·S3·Bedrock 세 개만 사용 가능.** RDS·DynamoDB(→SQLite), Cognito(→데모 계정 세션 쿠키), SES·SNS(→알림 불가), Lambda·API Gateway(→Next.js 단일 프로세스) 금지. 리전 ap-northeast-2 환경 상속, 버킷 접두사 `hackathon-e2-t01-`, Access Key 생성 금지(EC2 역할만).
- deploy/destroy·EC2 종료·재시작 금지(D-12).
- 개인정보: 교수 이름·연락처·이메일·면담·민원 정보는 저장·표시·색인 금지. 원본 PDF·zip은 Git·S3 앱 버킷에 넣지 않는다.
- 생성 모델: Bedrock `global.anthropic.claude-sonnet-5`. 벡터 DB·FAISS 금지, 검색은 결정론적 키워드 방식.

## 단계별 계획

데모 동선 순서대로 배치 — **중간에 시간이 부족해도 앞 단계까지는 데모가 성립한다.**

### 0단계. 스코프 재잠금 (문서 개정)
피벗을 문서에 반영: `IDEA.md`(한 줄·안 하는 것·데모 시나리오 개정), `docs/prd.md`(온보딩 FR-7, 추천 FR-8, 시간표 FR-9, 로그인 FR-10, 교수 리포트 FR-11 신설; FR-5 중복 차단을 `(course_id, user_id)`로), `docs/demo-script.md`(아래 "새 데모 동선"으로 재작성), `docs/architecture.md`(테이블·라우트 추가 반영).
**완료 기준**: 문서 간 모순 0건(특히 "로그인 없음"·"고급 개인화 제외" 문구 제거).

### 1단계. 데이터 파이프라인 (모든 것이 여기 의존)
- **과목 카탈로그**: 3개 학과 zip + 교양 zip에서 학과별 8~12과목 선별 → `catalog.json`. 필드 최소화: 과목ID, 과목명, 학과, 개요 2~3문장, 목표 키워드, 난이도, 선수지식, 관련 관심분야 태그. 시간·요일은 데모 프리셋 부여.
- **대표 과목 풀 구조화**: `웹컨텐츠개발.pdf` → `course.json`(1~15주 주제·목표·과제, sourceKind) + `demo-supplement.json`(준비물·공지) + `demo-tips.json`(12건).
- **완료 기준**: 카탈로그 25과목± 로드 성공, 대표 과목 15주 전부 존재, 개인정보 문자열 grep 0건.
- ⚠️ 개인정보 제거 산출물은 **사용자가 최종 육안 검수**.

### 2단계. 앱 뼈대 + DB + 로그인 + 온보딩
- `apps/web` Next.js App Router + TS 스캐폴드(pnpm, Node 20+).
- SQLite 마이그레이션: `users(id, name, role)`, `user_profile(user_id, major, interests, goal, career, style, hours, avoid)`, `user_courses`(시간표), `checklist_state`(보상 계산용으로 DB 저장), `course_tips`, `qa_logs`.
- 로그인: `/login` 데모 계정 선택(학생·교수) → 세션 쿠키. 회원가입·인증 라이브러리 금지.
- 온보딩: 로그인 후 7스텝 위저드(전공→관심분야→목표→진로→학습스타일→시간→선호/비선호), 각 스텝 단일 선택 칩 + 건너뛰기, 완료 시 `user_profile` 저장.
- **검증**: `pnpm dev` 부팅, seed 후 계정 2개, 온보딩 완료 → 프로필 조회, 교수 로그인 시 `/professor` 리다이렉트.

### 3단계. 과목 추천 + 추천 이유
- `/api/recommend`: ①결정론적 사전 필터 — 비선호 분야 제외, 전공·관심분야 태그 매칭, 시간 조건으로 후보 10~15개 ②Bedrock에 후보 요약 + 프로필 → 상위 3~5과목, **각각 "왜 나에게 맞는지" 이유**(전공 연계·목표 부합·시간 적합 중 근거 명시).
- Bedrock 실패 시: 사전 필터 결과를 이유 없이 표시 + "AI 추천 이유를 생성하지 못했습니다" 폴백.
- **검증**: 비선호 분야 과목이 결과에 0건(단위 테스트), 프로필 2종으로 서로 다른 추천 확인, 폴백 동작.

### 4단계. 시간표 메인 화면
- 추천 결과에서 "시간표에 담기" → `user_courses` 저장 → 메인 주간 그리드 렌더. 과목 클릭 → 상세 페이지 이동.
- **검증**: 담기/빼기 반영, 새로고침 후 유지, 키보드로 과목 셀 진입 가능.

### 5단계. 과목 상세 페이지 (기존 MVP 편입)
- 대표 과목: 로드맵 15주(FR-1) + 이번 주 코치(FR-2: 준비물·과제·**개인 목표 반영 체크리스트**, 완료 상태는 `checklist_state`) + 출처 배지.
- 카탈로그 과목: 개요·선수지식·사전 자료 요약 카드(얇은 버전).
- **검증**: prd FR-1·FR-2 기준 충족, actual/demo 배지 데이터 일치.

### 6단계. 출처형 Q&A + 근거 없음 로깅
- 대표 과목 상세에서 FR-3 그대로: 결정론적 검색 → 근거 있으면 Bedrock, 없으면 `not_found` 즉시 반환(모델 미호출) + `qa_logs` 적재.
- **검증**: 3상태 API 테스트. 로컬은 Bedrock 불가(EC2 역할만)이므로 `model_error` 폴백으로 검증, 실답변은 EC2에서.

### 7단계. 보상 + 팁 + 교수 리포트
- 보상: 마스코트 1종(logo.png 활용)이 체크리스트 완료율 0/50/100%에서 3단계 변화. 온보딩·메인에 상시 노출.
- 팁: FR-4·5 재사용, 중복은 `(course_id, user_id)` 409.
- 교수 리포트 `/professor`(읽기 전용): 근거 없음 질문 목록 + 팁 집계. 학생 접근 차단.
- **검증**: 체크 완료 → 캐릭터 단계 변화, 팁 제출 → 집계 갱신, 학생이 남긴 근거 없음 질문이 교수 화면에 표시.

### 8단계. 접근성 + 여유 시 항목
- 필수(FR-6): 키보드 탐색, 포커스 표시, aria-live, Web Speech 읽어주기(부재 시 비활성).
- 여유 시: ①능력 변화 대시보드 — `데모 데이터` 배지 단 시뮬레이션 전/후 그래프 ②말투 모드(순한맛/중간맛/매운맛, Q&A 프롬프트 변형 + 캐릭터 표정).
- **검증**: 마우스 없이 데모 동선 전체 통과.

### 9단계. 데모 리허설 + 배포 (사용자 승인 후)
- **계획됨(현재 미구현):** 새 데모 동선 전체 로컬 리허설 → 정제 JSON S3 업로드 → EC2 배포.
- 배포 전 검사: 원본 zip·PDF·PEM·.env가 빌드·Git 대상에 없는지 grep.
- ⚠️ D-12: 배포·EC2 조작은 사용자 명시 승인 후에만.

## 새 데모 동선 (0단계에서 demo-script.md로 옮길 초안)

1. 학생 데모 계정 로그인
2. 온보딩 7스텝 — "학생을 이해하는 AI" 슬로건 노출
3. 과목 추천 3~5개 + 각 추천 이유 확인
4. 추천 과목을 시간표에 담고 메인 시간표 확인
5. 대표 과목 상세: 15주 로드맵 + 이번 주 준비·체크리스트(개인 목표 반영) + 출처 배지
6. 출처형 Q&A: 근거 답변 → 문서에 없는 질문 → 근거 없음 정직 응답
7. 체크리스트 완료 → 캐릭터 성장 보상
8. 수강생 팁 제출 → 집계 갱신
9. 교수 계정 전환 → 근거 없음 질문 리포트 + 팁 집계 ("공지 한 번으로 N명의 질문 해결")
10. 읽어주기 + 키보드 전용 탐색

## 리스크 (정직 고지)

- 구현률 0%에서 범위가 커졌다. 절대 방어선은 **1~6단계**(추천→시간표→상세→Q&A) — 이것만으로 슬로건이 성립한다. 7단계 이후는 시간 보고 자른다.
- 1단계 카탈로그 구조화(PDF 수십 개)가 최대 변수 — 과목 수를 줄이는 한이 있어도 필드를 늘리지 않는다.
