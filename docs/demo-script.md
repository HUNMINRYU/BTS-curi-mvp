# CURI 심사위원 데모 스크립트

## 데모 전제
- 과목: 웹컨텐츠개발
- 실제 `웹컨텐츠개발.pdf`의 개인정보 제거 파생 데이터는 `실제 강의계획서`, 보충 공지·실습 안내문과 초기 수강생 응답 12건은 `데모 데이터`로 표시한다.
- 사용자는 로그인하지 않는다. 브라우저 세션당 해당 과목의 학습 팁을 한 번 제출할 수 있다.
- 데모 중 AWS 리소스를 생성·배포하지 않는다.

## 1. 한 학기 흐름 확인
첫 화면에서 웹컨텐츠개발 1~15주 로드맵을 연다. 현재 주차, 완료 주차, 다음 주차, 중간고사·기말 프로젝트 이정표가 구분된 것을 확인한다.

**보여줄 핵심:** CURI는 문서 검색창이 아니라 학생이 현재 위치를 파악하는 수업 내비게이터다.

## 2. 이번 주 준비 행동 확인
현재 주차를 선택해 수업 주제, 학습목표, 수업 전 준비, 과제, 오늘의 체크리스트를 확인한다. 각 항목의 출처 유형을 확인하고 체크리스트 하나를 완료 처리한다.

**보여줄 핵심:** 실제 강의계획과 표시된 보충 데이터를 준비 행동으로 바꾼다.

## 3. 공식 문서 기반 질문
`실습 전에 무엇을 준비해야 하나요?`를 질문한다. 답변에서 준비 항목과 함께 출처 문서명, 해당 주차, `실제 강의계획서` 또는 `데모 데이터` 배지를 확인한다. 출처를 선택해 근거 문구를 확인한다.

이어서 공식 문서에 없는 질문을 입력했을 때 Bedrock을 호출하지 않고 `공식 문서에서 근거를 찾지 못했습니다. 담당자에게 확인해 주세요.`가 표시되는 것을 확인한다.

**보여줄 핵심:** 표시된 공식 강의정보만 사실 답변의 근거로 사용한다.

## 4. 수강생 학습 팁 확인
과목 상세의 `수강생 학습 팁` 영역에서 응답 수, 선수지식 필요도, 실습 비중, 과제량, 자주 선택된 준비 태그를 확인한다. 이 영역이 `수강생 참고 정보`이며 공식 강의정보와 별도임을 확인한다.

**보여줄 핵심:** 무단 강의평 수집 없이 동의 기반 경험정보를 안전하게 활용한다.

## 5. 구조화 팁 제출과 집계 갱신
선수지식 필요도·실습 비중·과제량을 각각 3단계로 선택하고, 준비 태그를 복수 선택한 뒤 동의 체크와 함께 제출한다. 응답 수와 평균·태그 빈도가 즉시 갱신되는 것을 확인한다. 같은 브라우저 세션에서 재제출이 차단되는 것을 확인한다.

**보여줄 핵심:** 자유서술 원문 없이도 행동 가능한 학습 팁을 축적한다.

## 6. 접근성 사용
이번 주 핵심 안내의 `읽어주기`를 실행하고 중지한다. 마우스를 사용하지 않고 Tab, Shift+Tab, Enter로 로드맵, 체크리스트, 질문 입력, 학습 팁 영역을 이동한다. 포커스 표시와 상태 변경 안내를 확인한다.

**보여줄 핵심:** 접근성은 별도 서비스가 아니라 핵심 흐름 전체에 적용된다.

## 데모 완료 조건
- 6단계 전체가 한 브라우저 세션에서 완료된다.
- 실제 강의계획서, 데모 데이터, 수강생 참고 정보가 시각적으로 구분된다.
- AI 답변에는 출처가 있거나 명시적인 근거 없음 상태가 있다.
- 팁 제출 전후 집계 변화가 보인다.
- 읽어주기와 키보드 탐색이 실제 동작한다.
