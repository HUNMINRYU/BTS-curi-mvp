# CURI 심사위원 데모 스크립트

## 데모 전제
- 학생·교수 데모 계정만 사용하며 회원가입은 없다.
- 추천 카탈로그는 약 25과목, 풀 상세는 `웹컨텐츠개발`이다.
- 실제 파생 정보는 `실제 강의계획서`, 프리셋·보충·초기 팁은 `데모 데이터`로 표시한다.
- 데모 중 AWS 리소스를 생성·배포하지 않는다.

## 1. 학생 로그인
`학생 데모` 계정을 선택해 로그인한다. 온보딩 미완료 학생은 자동으로 온보딩으로 이동한다.

**보여줄 핵심:** 역할 구분에 필요한 최소 로그인만 제공한다.

## 2. 학생을 이해하는 7단계 온보딩
전공→관심분야→목표→진로→학습스타일→투자 시간→비선호 분야를 단일 선택 칩으로 완료한다. 진행률과 슬로건 `학생을 이해하는 AI`를 확인한다.

**보여줄 핵심:** 문서 분석보다 학생 맥락을 먼저 얻는다.

## 3. 과목 추천과 이유
추천 3~5개를 확인한다. 각 카드에서 전공 연계·목표 부합·시간 적합 중 프로필에 근거한 이유를 확인하고 비선호 분야가 없는지 확인한다.

**보여줄 핵심:** 추천 목록이 아니라 “왜 나에게 맞는가”를 설명한다.

## 4. 시간표 메인
추천 과목 하나를 `시간표에 담기`로 추가한다. 주간 그리드에 표시되고 새로고침 후 유지되는지 확인한다. 키보드로 과목 셀에 진입해 상세로 이동한다.

**보여줄 핵심:** 추천을 실제 수강 계획과 매일의 진입점으로 바꾼다.

## 5. 대표 과목 상세
`웹컨텐츠개발`의 1~15주 로드맵, 현재 7주차, 중간·기말 이정표를 확인한다. 이번 주 주제·목표·과제·준비물과 온보딩 목표가 반영된 체크리스트를 확인한다. 실제/데모 출처 배지를 구분한다.

**보여줄 핵심:** 기존 MVP의 수업 내비게이터가 추천 이후 행동까지 이어진다.

## 6. 출처형 Q&A와 근거 없음
`실습 전에 무엇을 준비해야 하나요?`를 질문해 문서명·주차·근거 문구를 확인한다. 이어 공식 문서에 없는 질문을 입력해 `공식 문서에서 근거를 찾지 못했습니다. 담당자에게 확인해 주세요.`를 확인한다.

**보여줄 핵심:** 근거 밖을 추측하지 않고 필요한 공지 신호를 남긴다.

## 7. 체크리스트 보상
체크리스트를 완료해 완료율과 CURI 상태가 0%→50%→100% 단계에서 바뀌는 것을 확인한다.

**보여줄 핵심:** 학생이 매일 다시 열 이유를 만든다.

## 8. 수강생 학습 팁
세 척도와 준비 태그, 동의를 제출한다. 집계가 즉시 갱신되고 같은 학생 계정의 재제출이 HTTP 409 메시지로 차단되는지 확인한다.

**보여줄 핵심:** 자유서술 없이 행동 가능한 경험정보를 축적한다.

## 9. 교수 리포트
로그아웃 후 `교수 데모`로 로그인한다. 근거 없음 질문 목록·횟수와 팁 집계를 확인한다. 학생 식별정보, 답글, 업로드 기능이 없음을 확인한다.

**보여줄 핵심:** 공지 한 번으로 반복 질문을 줄일 수 있는 읽기 전용 신호다.

## 10. 접근성
학생으로 돌아와 이번 주 안내의 읽어주기를 시작·중지한다. 마우스 없이 Tab·Shift+Tab·Enter로 로그인, 온보딩, 추천, 시간표, 과목 상세, Q&A, 팁을 이동한다. 포커스와 `aria-live` 상태를 확인한다.

**보여줄 핵심:** 접근성은 별도 화면이 아니라 전체 핵심 동선에 적용된다.

## 완료 조건
- 10단계가 로컬 브라우저에서 완료된다.
- 추천 이유는 저장된 프로필에 근거하고 비선호 분야를 포함하지 않는다.
- 시간표·체크리스트가 새로고침 후 유지된다.
- 실제 강의계획서·데모 데이터·수강생 참고 정보가 시각적으로 구분된다.
- Q&A는 출처 또는 근거 없음 상태를 갖고, 근거 없음 질문은 교수 리포트에 나타난다.
- 팁은 로그인 사용자당 과목 1회다.
- 학생은 교수 리포트에 접근할 수 없다.
- 키보드 탐색과 읽어주기가 실제 동작한다.
