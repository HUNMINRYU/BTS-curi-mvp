## 심사위원에게 (1,000자 이내)

```text
CURI는 학생 프로필을 바탕으로 과목과 추천 이유를 제시하고, 시간표·주차별 준비·공식 근거 Q&A·교수 익명 리포트까지 연결합니다.

실행: 배포 주소 접속 → 회원가입 → 7단계 온보딩 → 추천 과목 확인·시간표 담기 → 웹컨텐츠개발 상세 → 체크리스트·Q&A → 프로필 랭킹 → 로그아웃 후 교수 계정 전환.

데모 계정: student-test(학생), professor-test(교수). 비밀번호는 발표 현장에서 별도 제공합니다.

AWS: EC2에서 nginx/Next.js/SQLite/FAISS sidecar 실행, Bedrock Claude가 추천 이유·근거 기반 답변 생성, Titan Text Embeddings v2가 질문 임베딩 담당. S3 문서 동기화·재색인은 현재 런타임과 분리된 수동 운영 계획입니다.

제약: 로컬 환경에서는 Bedrock·FAISS 자격증명이 없어 결정론적 폴백/근거 없음으로 동작할 수 있습니다.
```

## AWS·AI 설명

1. 브라우저 요청은 EC2의 nginx를 거쳐 Next.js로 들어온다.
2. 사용자·프로필·시간표·체크리스트·팁·포인트는 EC2 SQLite에 저장한다.
3. Q&A는 EC2 로컬 FAISS sidecar가 먼저 공식 강의 근거를 검색한다.
4. 근거가 있을 때만 Bedrock Claude가 답변을 생성한다.
5. Titan Text Embeddings v2는 질문을 검색 벡터로 변환한다.
6. 추천은 결정론적 후보 점수와 Bedrock 개인화 이유를 결합한다.
7. 답변·인용의 전화번호와 이메일은 API 응답 경계에서 마스킹한다.
8. S3 `documents/` 동기화와 재색인은 현재 배포에 자동 연결되지 않은 수동 운영 계획이다.

```text
Kiro를 단순 코드 생성기로 사용하지 않고 요구사항 정의 → 화면·데이터 구조 설계 → 기능 단위 작업 분해 → 테스트와 검증 반복에 활용했습니다. 초기 강의계획서 Q&A 아이디어를 학생 프로필 기반 추천·시간표·준비 행동·교수 리포트 흐름으로 재정의했고, 각 기능은 실패 테스트를 먼저 만들고 구현·브라우저 QA·문서 정합 검토를 반복했습니다.
```

## 3분 시연 순서

1. 신규 학생 가입과 7단계 온보딩 — 프로필·30P·뱃지
2. 추천 페이지 — 과목별 추천 이유와 강의계획서 출처
3. 시간표 담기 — 선택 요일/전체 시간표, 과목 상세 진입
4. 상세 페이지 — 15주 로드맵, 이번 주 체크리스트와 보상
5. Q&A — 공식 근거 답변과 근거 없음 질문 비교
6. 프로필 — 익명 준비왕·능력 변화
7. 교수 화면 — 익명 학급 현황과 근거 없음 질문
