# CURI MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and demonstrate CURI as a one-course Next.js application that separates actual syllabus facts, marked demo supplements, and aggregated student tips.

**Architecture:** A single Next.js App Router process serves UI and route handlers. Course data is privacy-scrubbed JSON, student tips use SQLite, grounded Q&A uses deterministic retrieval plus Amazon Bedrock, and deployed course JSON is mirrored in S3.

**Tech Stack:** Node.js 24, pnpm 11, Next.js 16, React 19, TypeScript, Vitest, Playwright, better-sqlite3, AWS SDK v3, AWS CDK v2

**Spec:** `docs/prd.md`, `docs/architecture.md`, `docs/demo-script.md`, `docs/decisions.md`

## Global Constraints

- Demo course is exactly `웹컨텐츠개발`.
- Every official-data citation has `sourceKind: "actual" | "demo"` and renders `실제 강의계획서` or `데모 데이터`.
- Raw syllabus PDFs and archives, professor/contact data, free-text reviews, direct identifiers, IP addresses, and AWS access keys never enter the application data or Git.
- Student tips are not searchable and never enter Bedrock prompts.
- Tip aggregates are hidden below 5 responses; 12 initial responses are marked demo data.
- AWS region comes from the SDK default provider chain; do not hard-code another region.
- `deploy`, `destroy`, and EC2 stop/restart require explicit user instruction.
- Local demo completion precedes all AWS deployment work.
- Each task gets its own verified commit; never combine later feature work into an earlier commit.
