# 2차 검토 (같은 날 17:00) — LMS 차별점 · 커뮤니케이션 · 추가 아이디어

## LMS와의 차별점 (발표용 핵심 프레임)
**"LMS는 주 1회 의무로 가는 곳, CURI는 매일 자발적으로 여는 곳."**

설득은 양쪽 모두에게 성립해야 채택된다 — "학생은 매일 열 이유가 있고, 교수는 올릴 이유가 있다":

**학생이 LMS 대신 CURI를 여는 이유 3가지**
1. 열면 3초 안에 "오늘 뭘 준비해야 하는지" 나옴 — LMS는 공지·파일을 스스로 조립해야 함
2. 질문하면 출처 붙은 즉답 — 교수 답장·에타 검색을 기다리지 않음
3. 내 목표·수준에 맞춘 가이드 + 캐릭터 성장 = 매일 여는 습관 루프(듀오링고 프레임)

**교수가 CURI에 문서를 올리는 이유 3가지**
1. 추가 노동 0 — 이미 작성한 강의계획서를 그대로 재사용
2. "시험범위 어디까지예요?" 반복 질문 메일이 AI로 흡수됨 = 시간 절약
3. 근거 없음 질문 리포트가 "어떤 공지가 필요한지"를 자동으로 알려줌

**콜드스타트 해법:** 교수가 참여하지 않아도 학생이 공개된 강의계획서만 넣으면 동작 — 학생 단독으로도 가치가 성립하고, 교수는 나중에 합류해도 된다.

**주의(심사 방어):** "LMS 완전 대체" 주장은 과제 제출·성적·출결 같은 행정 기능 때문에 공격받기 쉬움. "LMS는 제출할 때만, 학습은 CURI에서"로 사용 빈도 프레임을 유지할 것.

1. LMS는 문서를 **보관**, CURI는 문서를 **행동으로 변환** — 이번 주 준비물·체크리스트·선수지식 추천.
2. **출처형 AI Q&A** — 근거 배지 + 근거 없음 정직 응답. LMS에는 없는 기능.
3. 학기 전체 **현재 위치·이정표 내비게이션** vs LMS의 주차별 폴더 나열.
4. **동의 기반 구조화 수강생 팁** — 에타 강의평의 무단 수집·비방 문제 없이 얻는 peer signal.
5. 접근성 우선 설계.

## 교수–학생 커뮤니케이션 해결 방안 (커뮤니티 없이)
대댓글·게시판이 아니라 **"질문 흡수 + 신호 전달" 구조**로 해결한다:

1. **출처형 Q&A가 반복 질문을 흡수** — 시험범위·준비물·마감 등 문서에 답이 있는 질문은 AI가 즉답 → 교수에게 가는 질문 자체를 줄임.
2. **근거 없음 질문 로그 → 교수 전달** — "학생들이 물었는데 문서에 답이 없던 질문" 집계(설계 §7 운영자 인사이트의 최소 버전). 교수는 공지 한 번으로 N명의 질문을 해결. 자유 텍스트가 교수·학생 사이에 직접 오가지 않으므로 신고·차단·금칙어가 전부 불필요.
3. **구조화 팁 집계** = 학생→교수 방향 익명 신호(과제량·실습 비중 체감).
